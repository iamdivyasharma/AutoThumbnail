Contract Info Extractor- Guide for Streamlit + FastAPI backend(What’s Implemented & How to Use It)
This document explains exactly what Streamlit app and FastAPI backend do, and provides the payloads and sample JSON:
Client Content Explorer — Excel sheet


Summary of contracts — Excel chat (RAG over workbook)


Generic QA bot — chat with PDFs (local files; S3 names mapped to local)


Source list of URLs


Document viewer (including highlight annotations-tried/not working)


It also maps each feature to the functions/endpoints that implement it in the code.

Streamlit (frontend)


CONTRACT_API_URL → FastAPI base (default http://localhost:8000)


CONTRACT_EXCEL_PATH → Local Excel used for Client Content Explorer


CONTRACT_LOCAL_PDF_DIR → Local PDFs folder (default pdfs/) (local here means AWS studio instance)


FastAPI (backend)


FAISS_INDEX_DIR → Absolute path to per-client FAISS indexes ( contain index.faiss and index.pkl for each client)


CONFIGS_PATH → Absolute path to configs/clients.yaml (aliases & per-client overrides)


PDFS_DIR (derived from CONTRACT_LOCAL_PDF_DIR) → Local PDFs directory served at /local-pdfs


Excel: LOCAL_EXCEL_PATH, LOCAL_EXCEL_INDEX_DIR


Static PDFs (served by FastAPI): /pdfs/<filename>.pdf



1) Client Content Explorer — Excel Sheet (Streamlit-only)
What it does:
Streamlit reads a local Excel file (CONTRACT_EXCEL_PATH).


It auto-detects columns using these aliases:


client: Client Name, Client, Client_Name, client, client name


category: Category, categrpy, Clause, Topic, Label, category


content: Client Content, Content, Text, Details, Answer, client content


UI lets you select a client; shows all the column int he table (Clause, Sub clause Content…etc.  


Where in code:
Streamlit: load_excel(), _first_matching_column(), and the Client Content Explorer block that renders a dataframe.


No backend API is called in our current implementation. (CAN ADD IT to fastAPI- let us know*)





2) Summary of Contracts — Excel Chat (Excel RAG)
The backend builds a FAISS index over the Excel workbook and  the Streamlit Excel Chat panel calls these endpoints.
Where in code:
FastAPI: /excel/metadata, /excel/chat, /excel/refresh, /excel/history/{session_id}


Streamlit helper functions: _excel_fetch_metadata(), _excel_chat(), _excel_refresh(), _excel_get_history(), _excel_clear_history()


2.1 GET /excel/metadata
Returns workbook info for display. 
Sample response   
{
  "path": "/xxx//client-clause.xlsx",
  "mtime": "2025-10-12T17:02:11",
  "sheets": ["Contracts", "Clients", "Definitions"],
  "rows": { "Contracts": 1234, "Clients": 88, "Definitions": 210 },
  "last_loaded_at": "2025-10-12T17:03:42Z"
}

2.2 POST /excel/chat
Ask any question about the Excel workbooks.
Request
{
  "question": "tell me all the clients having a technology clause.",
  "session_id": "xx",
  "k": 6
}

Sample response
{
  "answer": "for technology clause : two client named……etc",
  "sources": [
    { "sheet": "Contracts", "start_row": 401, "end_row": 440, "snippet": "[sheet: Contracts] rows 401-440 ..." },
    { "sheet": "Contracts", "start_row": 721, "end_row": 760, "snippet": "[sheet: Contracts] rows 721-760 ..." }
  ],
  "history": [
    { "role": "user", "text": "for technology clause : two client named……etc.", "time": "vv" },
    { "role": "assistant", "text": "xxxxxxx", "time": "xx" }
  ],
  "meta": {
    "path": "/abs/path/to/data/workbook.xlsx",
    "mtime": "xx",
    "sheets": ["Contracts", "Clients"]
  }
}


2.3 POST /excel/refresh
Rebuild the Excel FAISS index.
Sample response
{
  "status": "ok",
  "message": "Excel reloaded and indexed.",
  "meta": {
    "path": "/xxx/client-clause.xlsx",
    "mtime": "xx",
    "sheets": ["client-clause""],
    "rows": { "clients": 16, "clauses": 35…. }
  }
}

2.4 GET /excel/history/{session_id}
Sample response
{
  "session_id": "d1b1d6d7-4b67-4cd9-9f3f-13b9c7a7a1d3",
  "history": [
    { "role": "user", "text": "...", "time": "2025-10-12T17:01:00Z" },
    { "role": "assistant", "text": "...", "time": "2025-10-12T17:01:01Z" }

2.5 DELETE /excel/history/{session_id}
Sample response
{ "status": "ok", "session_id": "xx", "cleared": true }


3) Generic QA Bot — Chat with PDFs (local or S3-named)
What it does:
Detects clients from the question (or accepts client_ids).


Retrieves from each client’s FAISS store (strict client filtering), then asks the LLM.


Returns the answer and per-source page hits with optional highlights.


Where in code:
FastAPI:
POST /ask
GET /clients, 
GET clients/{client_id}/documents
static PDFs at /pdfs.


Streamlit: the PDF RAG section (normalizing client names, sending /ask, then rendering answer & sources). Also Open in viewer buttons use the returned metadata.


3.1 GET /clients
Sample response
["bmw us", "estee lauder",...etc]

3.2 GET /clients/{client_id}/documents
Lists per-client documents (from the client’s manifest), mapped to local (aws instance) PDFs by filename(Currently from Sagemaker studio *local* - would fetch it from s3 soon)
Sample response
[
  {
    "policy_id": "BMW_US",
    "source_file": "/pdfs/BMW_policy1.pdf",
    "pages": 78,
    "client_id": "bmw us",
    "Modified_time": xxx,
    "modified_iso": "xxx"
  },
 ……
]

3.3 POST /ask
Request (explicit clients; omit client_ids to rely on auto-detection)
{
  "question": "What are the data protection obligations for BMW US and Estee Lauder?",
  "client_ids": ["bmw us", "estee lauder"]
}

Sample response
{
  "answer": "For BMW US, late delivery penalties are ... For Estee Lauder, data protection obligations include ..et c.",
  "used_clients": ["bmw us", "estee lauder"],
  "sources": [
    {
      "policy_id": "BMW_US”,
      "page": 14,
      "client_id": "bmw us",
      "source_file": "/pdfs/BMw_MasterServices.pdf",
      "annotations": [
        { "page": 14, "x": 120.3, "y": 245.6, "width": 380.2, "height": 18.7, "color": "yellow" }
      ]
    },
    {
      "policy_id": "EL_2021_Master",
      "page": 33,
      "client_id": "estee lauder",
      "source_file": "/pdfs/EL_signedpolicy.pdf",
      "annotations": [
        { "page": 33, "x": 96.5, "y": 502.0, "width": 410.0, "height": 19.0, "color": "yellow" }
      ]
    }
  ]
}

Notes
used_clients shows which clients were actually used for retrieval.


Each source contains a local PDF URL (/pdfs/...) and highlight rectangles for the specified page.



4) Source List of URLs
You can extract these URLs from:
/ask → sources[*].source_file


/clients/{client_id}/documents → each item’s source_file


Example extracted list
[
  "/pdfs/BMW_policy1.pdf",
  "/pdfs/EL_signedpolicy.pdf"
]


5) Document Viewer
What it does:
Streamlit displays the selected PDF.


Scrolls to the returned page number.


If provided, draws yellow highlight rectangles returned by the backend.


Where in code:
Streamlit: Right-side Document Viewer panel using streamlit_pdf_viewer.pdf_viewer(...).


Backend: PDFs are served as static files at /pdfs/<filename>.pdf via StaticFiles.


Data to open a doc in the viewer
{
  "source_file": "/pdfs/EL_signedpolicy.pdf",
  "page": 33,
  "annotations": [
    { "page": 33, "x": 96.5, "y": 502.0, "width": 410.0, "height": 19.0, "color": "yellow" }
  ]
}

Binary route
GET /pdfs/<filename>.pdf → serves the raw PDF file (no JSON).


SECTIONS IN UI:

 Client Content Explorer — Directly from Excel sheet: implemented in Streamlit only (no backend call). 


 Summary of contracts — Excel chat:  /excel/chat (+ metadata, refresh, history).


 Generic QA bot — PDFs:  /ask (+ /clients, /clients/{id}/documents).


 Source list of URLs: comes from /ask.sources[*].source_file and /clients/{id}/documents[*].source_file.
